# Script memory: game_catalog.lua

Role: versioned remote UI module for the reworked game/script catalog.

The module returns a frozen contract-version-1 table with one `Create(context)` factory. It is fetched from the `codex/ui-rework` raw GitHub branch and compiled only through executor `loadstring`; it is never adapted for Roblox Studio and has no embedded fallback inside `loader.lua`.

The factory receives `InterfaceRoot`, the shared `Base`/`Layer`/`Signal` plus semantic `Success`/`Warning`/`Danger` colors, shared Nunito/BuilderSans fonts, all catalog layout/motion tokens, input/audio/lifecycle services, live anchor/viewport providers, a copied catalog-entry provider, and loader-owned execution/cover services. It constructs one hidden `GameCatalogRoot` and returns a frozen controller exposing only `Open`, `Close`, `Toggle`, `IsOpen`, and `Destroy`. It contains no private palette, font, duration, or layout registry.

Revision-5 composition: responsive maximum 780×520 popup; opaque 60 px header and 42 px footer; 20%-transparent normal `Frame` body plus one temporary non-interactive reveal overlay; fixed 220 px centered `Oyun Kataloğu` title; upper-left `Tümü` switch; right search and close controls; a hover-revealed clipped 160×36 search shell whose input and internal right-side 48 px result count never overlap; vertically scrolling three-column content with 20 px body padding and 12 px gaps; equal integer-pixel card widths plus a glow-derived safety inset at every scroll boundary; 238 px cards with a 142 px automatic Roblox cover, a colored 13 px status strip inside the cover's bottom edge, larger name, and centered-dot feature summary. The bottom-center outcome toast is reduced to 280×30 with 12 px text. Run hints and static footer explanations remain removed. Header, footer, and the collapsed search shell's exact 160×36 location update one viewport-clamped resting position; opening search hides the overlapping drag receiver until the shell collapses.

The official status and feature maps are private and frozen. MM2 is `Stable`; entries without a remote built-in mapping receive remote default `Supported`; entry-provided `Status` and `Features` fields are discarded. No setter or map is returned. Thirteen remote-owned non-executable previews provide enough data to verify multiple 3×3 virtual pages and resolve real-game covers only when their page is active. All previews are `Un-Supported`. The default filter therefore shows only `Stable`/`Supported` executable entries; the `Tümü` switch reveals the previews and any other unsupported entries. Preview and `Un-Supported` cards never call the execution service.

The metadata list is sorted once by status priority `Stable`, `Supported`, `Un-Supported`, then by lowercase display name and stable ID. Search and the `Tümü` status filter preserve that order. Every `Open` creates a new content-generation revision: filtering and scroll reset occur while rendering is gated, then the current row plus the next two rows are constructed exactly once—no more than nine card trees—and uncovered by the lightweight 0.36-second overlay transition alongside window motion. The nested body `CanvasGroup` from revision 4 is removed. The active page remains intact through closing motion and is disconnected/destroyed only after successful close completion; the filtered view, canvas, visibility, and session-local cover cache are also reset. Late asynchronous cover results compare their captured generation before caching or applying. Every following open therefore reloads visible cards and covers, while invisible scripts have no card, hover connection, or cover request.

Open/close uses a revision-guarded fixed-layout origin transition. The corner launcher has no delayed callback, and open/close create their motion tweens synchronously before spawning only completion waiters. The window starts moving in the same activation call, then the visible virtual page is created and its body reveal begins without a scheduled delay. It keeps its final pixel size, begins at the upper button's sampled center with whole-window scale 0, and moves to its saved center while scaling to 1. Close re-samples the button, moves there, reaches scale 0, and only then hides and releases active cards. No child size changes or reflows during the transition. Search, cover, and virtual-page continuations verify ownership/destroyed state.

Card hover uses the shared yellow `Warning` outline at one fixed 3 px thickness; the base outline remains a fixed 2 px. An unavailable or failed activation changes color/transparency—not thickness—to `Danger`, shakes only the card inside its layout slot, and shows a bottom-center red reason toast. Successful execution uses `Success` outline/toast without the failure shake. Outcome delays are revision-guarded so repeated clicks cannot let an older completion clear newer feedback.
