# Script memory: game_catalog.lua

Role: versioned remote UI module for the reworked game/script catalog.

The module returns a frozen contract-version-1 table with one `Create(context)` factory. It is fetched from the `codex/ui-rework` raw GitHub branch and compiled only through executor `loadstring`; it is never adapted for Roblox Studio and has no embedded fallback inside `loader.lua`.

The factory receives `InterfaceRoot`, the shared `Base`/`Layer`/`Signal` plus semantic `Success`/`Warning`/`Danger` colors, shared Nunito/BuilderSans fonts, all catalog layout/motion tokens, input/audio/lifecycle services, live anchor/viewport providers, a copied catalog-entry provider, and loader-owned execution/cover services. It constructs one hidden `GameCatalogRoot` and returns a frozen controller exposing only `Open`, `Close`, `Toggle`, `IsOpen`, and `Destroy`. It contains no private palette, font, duration, or layout registry.

Revision-7 composition retains revision 6 size, opacity, full-header/footer dragging, clipped status strips, virtualization, and reveal lifecycle. The former upper-left `Tümü` switch is removed. A 40 px three-line launcher opens one 260 px internal `FilterDrawer`, moves to its upper-right during the same animation, and returns to the header on close. The drawer never leaves `ContentClip`; one transparent dismiss button covers the remaining catalog and closes the drawer on the first outside click. Outer catalog close also starts drawer close.

The official status and feature maps are private and frozen. MM2 is `Stable`; entries without a remote built-in mapping receive remote default `Supported`; entry-provided `Status` and `Features` fields are discarded. No setter or map is returned. Thirteen remote-owned non-executable previews provide enough data to verify multiple 3×3 virtual pages and resolve real-game covers only when their page is active. All previews are `Un-Supported`. The default filter therefore shows only `Stable`/`Supported` executable entries; the drawer's `Tümünü Göster` switch reveals previews and any other unsupported entries. Preview and `Un-Supported` cards never call the execution service.

The metadata list is sorted once by status priority `Stable`, `Supported`, `Un-Supported`, then by lowercase display name and stable ID. Search, show-all, favorites-only, and feature filters preserve that order and compose. Feature strings are normalized into uppercase sets once; multiple selected square checkboxes require every selected feature. Favorites are keyed by stable built-in/place/name identity and remain only for the current hub lifetime. Every `Open` creates a new content-generation revision: filtering and scroll reset occur while rendering is gated, then the current row plus the next two rows are constructed exactly once—no more than nine card trees—and uncovered by the lightweight 0.36-second overlay transition alongside window motion. The active page remains intact through closing motion and is disconnected/destroyed only after successful close completion; the filtered view, canvas, visibility, and session-local cover cache are also reset. Late asynchronous cover results compare their captured generation before caching or applying. Every following open therefore reloads visible cards and covers, while invisible scripts have no card, hover/favorite connection, or cover request.

Each virtual card has a scoped favorite control built from Roblox client PNG `InspectMenu/ico_favorite_off.png` and `ico_favorite.png`. Default, hover, selected, and selected-hover states follow the theme contract without a new palette. Removing a favorite while the favorites-only switch is active immediately rebuilds the current filtered virtual page; otherwise only the local star animates. Recreated cards read the controller-level favorites table.

Open/close uses a revision-guarded fixed-layout origin transition. The corner launcher has no delayed callback, and open/close create their motion tweens synchronously before spawning only completion waiters. The window starts moving in the same activation call, then the visible virtual page is created and its body reveal begins without a scheduled delay. It keeps its final pixel size, begins at the upper button's sampled center with whole-window scale 0, and moves to its saved center while scaling to 1. Close re-samples the button, moves there, reaches scale 0, and only then hides and releases active cards. No child size changes or reflows during the transition. Search, cover, and virtual-page continuations verify ownership/destroyed state.

Card hover uses the shared yellow `Warning` outline at one fixed 3 px thickness; the base outline remains a fixed 2 px. An unavailable or failed activation changes color/transparency—not thickness—to `Danger`, shakes only the card inside its layout slot, and shows a bottom-center red reason toast. Successful execution uses `Success` outline/toast without the failure shake. Outcome delays are revision-guarded so repeated clicks cannot let an older completion clear newer feedback.

Successful execution may return an `Activate` callback from the loader. The card begins its normal close transition immediately and invokes that callback only after the catalog's existing close duration, causing the registered smaller game window to open from its new rail button. Failure leaves the catalog open. The view never discovers, registers, or themes game controllers itself.

Executor acceptance: retain all revision-6 checks, then verify the old header switch is absent; the three-line button and drawer animate together without leaving/clipping outside the catalog; the button lands at drawer upper-right; outside clicks close only the drawer; drawer controls remain usable; `Tümünü Göster`, `Favoriler`, search, and multiple feature filters compose with AND feature semantics; every checkbox fill/check animates; favorite PNG states match default/hover/selected/removal-hover rules; favorites survive scrolling, virtual-page destruction, and catalog close/reopen but clear on hub reload. Then verify failed execution keeps the catalog open; successful MM2 execution closes it, creates exactly one game-action button above the base pair, and opens MM2 only after close completes.
