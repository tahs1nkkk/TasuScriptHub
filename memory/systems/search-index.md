# System memory: search indexing

Keep the purpose: discover categories, feature controls, actions, and navigation targets from one query.

Rework requirements: index stable IDs plus normalized labels, aliases, category, description, and keywords; update incrementally when controls register/unregister; rank exact, prefix, token, and fuzzy matches predictably; never traverse raw UI descendants to build the index.

Main-menu revision 2 consumes stable descriptors with `RegistrationOrder`, `SectionOrder`, `MainCategory`, and `VisibleWhen`. It indexes nine categories and orders results category → section → control without `pairs()` ordering. Category rows use large primary text, section rows use inverse shared colors, and control rows use smaller translucent text. Selection opens the correct category/card, scrolls/highlights the control, clears/releases the textbox, and collapses search. The view never traverses `LegacyUIRoot` or its own descendants.

The revision-5 game catalog has a deliberately local metadata search that filters by name, place ID, built-in ID, remote status, and remote feature summary before virtual cards are created. Hovering the search control reveals the 160 px clipped shell, a non-empty query pins it open, clearing and leaving it collapses it, and the input reserves a separate internal 48 px result-count zone. While the shell is collapsed, its exact header position is an invisible window-drag receiver; that receiver is hidden for the complete expanded-search lifetime so textbox hover, focus, selection, and typing own the input. Search combines with the default unsupported-status filter, preserves status/alphabetic ordering, resets scroll to the first virtual page, and never traverses UI descendants. Successful close clears the filtered view and canvas; every open rebuilds that metadata view while card rendering is gated, then constructs one virtual page. It does not replace, register into, or fork the future global search index; catalog registration remains a later service migration.

Executor checks: empty query, pinned non-empty shell, exact/prefix/partial labels, duplicate labels, hierarchy/order, result count, category/section/control results, auto-expand target card, clear/close after selection, target scroll/highlight, page replacement cleanup, removed controls, and mouse activation. Dynamic game-controller controls remain outside this main index until their descriptor registration phase.
