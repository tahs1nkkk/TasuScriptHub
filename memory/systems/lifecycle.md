# System memory: lifecycle and unload

Every connection, instance, render-step binding, context action, tween, temporary camera state, character mutation, and executor-global export needs a single owner and cleanup path.

The second canonical execution must unload the first instance before creating the next one. Cleanup is idempotent and safe after partial initialization.

Feature controllers register resources by feature ID. UI overlays and animations register separately from gameplay behavior.

The loader's `BlurEffect` is created through `trackInstance`, tweened back to zero during normal exit, explicitly destroyed after that exit, and also covered by global unload cleanup for reloads or partial initialization.

The loader's single ambient `RenderStepped` connection owns both the 22-row halftone loop and the icon breathing/anchor-rock motion. TasuHub decal resolution runs in one asynchronous HTTP/file/custom-asset worker, retries at most 20 times, and adds no animation connection; it checks loader/icon ownership before every retry and before applying a result, so unload cannot recreate UI. The main loader sequence waits on the icon's `Loading`/`Ready`/`Failed` state before entry. Failure disconnects tracked connections, destroys tracked instances and the still-invisible `ScreenGui`, then raises an explicit error; no fallback instance is owned or cleaned up. The ambient connection remains covered by global unload and is explicitly disconnected once the full downward/fade exit completes.

Transient loader sounds and the exit cue's child `PitchShiftSoundEffect` remain tracked instances. Their cleanup delay respects an explicit target duration plus a one-second margin (minimum four seconds), preventing the stretched three-second soft UI exit cue from being destroyed before playback completes. The exit cue's scheduled start checks loader ownership and visibility before creating sound state, so unload cannot resurrect audio after cleanup.

The loader checkpoint worker is a single guarded task. Runtime reports only raise its monotonic target; the worker visits each of 30 indices once, stops if unload or loader ownership fails, and clears its running flag on exit. Every checkpoint sound is a tracked transient instance with a dedicated 0.8-second cleanup delay, preventing 30 short ticks from accumulating under the general four-second sound lifetime. `WaitForLoadingCheckpoints` also exits when unload or loader ownership ends, so partial initialization cannot deadlock cleanup.

The post-loader corner-action rail is owned by the main tracked `ScreenGui`. Its two base buttons and any loader-registered game-action buttons share the same tracked input path; silent visibility-bar input connections, global pointer change/end listeners, and viewport resize listener are also registered through the global connection tracker. Dynamic insertion recalculates the fixed stack bounds and dock position, and each game button owns one current controller callback plus one revision-guarded official-icon worker. The direction arrow is a child of the bar and reuses existing dock/toggle updates without adding a connection. Drag state is stored on `UI`, uses a 6 px threshold, and suppresses post-drag activation. Hide/show completion uses a revision guard before changing visibility. Late icon workers verify image and controller ownership before assignment; replacement or unload cannot apply stale image state. Button hover/click sounds are tracked transient instances and share the normal sound cleanup path. Slot 1 toggles the remote catalog controller; the canonical idempotent `unload` path destroys every registered game controller before the catalog and rail, then removes the visibility bar/arrow, drag/resize connections, late icon ownership, and all other runtime state without constructing an unload screen.

The remote game-catalog controller owns one `GameCatalogRoot` below `InterfaceRoot`, persistent search/filter-drawer/full-header/footer drag/scroll connections, controller-lifetime favorite and selected-feature maps, at most nine virtual card trees and their scoped connections, asynchronous active-page cover tasks, a current-open-only successful-cover cache, transition revision, drawer revision, content-generation revision, toast revision, and per-card feedback/favorite-visibility revisions. Drawer switch/checkbox connections are persistent controller controls; favorite hover/activation connections belong to their virtual cards and are disconnected on every page replacement. A delayed favorite hide checks destroyed state, its captured visibility revision, current card-hover state, and live parent before disabling the button, so an older exit cannot hide a new hover. Closed state owns zero card trees and keeps its scroll canvas hidden and empty while retaining only the small filter/favorite state tables for the current hub lifetime. Every `Open` invalidates prior cover work, clears the session cache, updates filters/scroll while rendering is gated, then constructs the current virtual page exactly once behind a temporary lightweight reveal overlay. A page swap disconnects every scoped card connection and destroys its nine-or-fewer slots before constructing the next page. Successful close completion—not close start—invalidates cover work, disconnects/destroys the active page, clears filtered records/cache/canvas, hides the scroll view, and resets the reveal overlay; drawer motion closes concurrently. Late cover/drawer/favorite completions verify captured revisions, while transition revision prevents stale close completion after reopen. Module connections are registered with the controller/global tracker as applicable; controller `Destroy` invalidates content/drawer work, clears active/session data, disconnects its persistent local list, and removes its root, and global unload calls it before the main connection/instance sweep. The upper corner slot toggles this controller immediately and no longer unloads TasuHub.

Each migrated game module owns its controller view and feature-local resources below the shared `InterfaceRoot`, but receives palette, motion, input, audio, viewport, and action-button anchor services from `GetGameUIContext`. MM2 owns one root, one heartbeat connection, its player-removal connection, drag listeners, highlights/billboards, and transition revision. Its `Destroy`/`Unload` path is idempotent, disables feature loops, removes feature instances, disconnects local connections, destroys the root, and clears its compatibility export. It must never destroy the shared hub root or corner rail.
