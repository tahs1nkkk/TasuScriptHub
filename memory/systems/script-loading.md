# System memory: script loading and catalog

Keep the user flow: built-in entries, saved entries, URL/source execution, edit/delete, banner lookup, and capability feedback.

Rework requirements: separate catalog data from its view; validate HTTPS URLs and source presence; return structured compile/runtime errors; version remote modules; prevent duplicate execution; preserve text/icon fallback when images fail.

The system consumes shared theme components and never constructs a private catalog palette or modal.

The upper post-loader corner button, using Roblox decal `137753054375497`, now opens the first reworked catalog view. It no longer invokes unload. The view is delivered by contract-version-1 `game_catalog.lua`, downloaded from the `codex/ui-rework` raw GitHub branch and compiled with executor `loadstring`; there is no embedded UI fallback. Loader-owned services remain responsible for validated execution and cover resolution, while the remote module owns only catalog composition, filtering, immutable display status, and open/close state.

`executeCatalogEntry` validates an entry, enforces the MM2 place constraint, requires HTTPS when source is absent, reports download/compile/runtime errors, and locks a stable entry identity after successful execution so it cannot be started twice within the same TasuHub lifetime. A successful game module must return a controller with `Open`; loader registers that controller, creates its action-rail button, and returns structured `{Ok, Message, Activate}` data. Failed download/compile/runtime/controller-registration attempts release the lock for correction/retry. The catalog consumes `Activate` only after its own close transition has started, so a successful launch closes the catalog and opens the game window from the new button's current dock position. The dormant legacy catalog wrapper consumes the same result only for compatibility; the new module writes results into its opaque footer rather than invoking the hidden legacy toast.

The remote module ignores every entry-provided `Status` and `Features` field. It freezes its private built-in metadata, assigns the remote default `Supported` to other real catalog entries, and exports no mutation path. Thirteen preview entries exist only to exercise filtering, sorting, virtualization, and real-game covers; all are explicitly `Un-Supported` and non-executable. They remain hidden until the filter drawer's show-all switch is enabled and surface a red reason toast rather than reaching `executeCatalogEntry` when revealed. Search, show-all, session favorites, and normalized multi-feature AND filters compose without changing authoritative ordering. This is runtime contract integrity, not encryption against an executor owner.

Automatic cover lookup follows `PlaceId → UniverseId → official 768×432 game thumbnail → TasuHub/Catalog/Banners/<PlaceId>.png → executor custom asset`. Failure retains the fixed cover fallback. Game-action icons use the separate official square-icon path and cache under `TasuHub/Catalog/GameIcons/<PlaceId>.png`; the direct `rbxthumb` source remains visible while that executor asset resolves. The catalog grid supports three cards per row and vertical scrolling; the current executable built-in data contains MM2, saved entries continue to flow from `State.Catalog`, and preview cards never enter saved state. Only the active 3×3 virtual page asks for covers; successful results are cached only for the current opening.

Executor checks: verify the remote module request and version contract; open/close from every dock edge; drag from every non-interactive header/footer region while confirming controls retain input; open/close/dismiss the internal drawer; combine name/status/place-ID search with show-all, favorites-only, and multiple feature choices; verify star states and favorite survival across virtualization plus catalog reopen; resolve all visible covers; confirm preview activation never reaches the execution service; load the built-in MM2 entry in and outside its game; confirm the catalog closes immediately, one square-icon action button is prepended, and the smaller MM2 window opens automatically; toggle that window from its button; load a saved controller-returning source entry; exercise duplicate activation, a bad URL, compile/runtime/controller errors, cover/icon failure, module failure, feedback colors/shake/toast, and unload during every transition.
